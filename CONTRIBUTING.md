# Contributing / Mitmachen

Issues and pull requests are welcome, in English or German.
Issues und Pull Requests sind willkommen, auf Englisch oder Deutsch.

## Before you start

- Bugs and ideas: open an issue first; for a bug attach the **diagnostics download** of the
  gateway entry and, if possible, the telegrams from the panel.
- New devices: the telegram (hex) of a teach-in and of a state change helps most.

## Rules that matter

- Configuration only through the UI; no YAML for devices.
- Standard and Eltako EEP variants stay in separate modules (`protocol/eep/std/`,
  `protocol/eep/eltako/`); `std/` is generated and never edited by hand.
- The protocol layer imports nothing from `homeassistant`.
- No EnOcean or Eltako third-party libraries, no copied code, no EnOcean Alliance files
  (see [NOTICE](NOTICE)).
- Code, comments and commits in English; UI translations in German and English;
  `README.md` and `README.de.md` are updated together.

## Checks

```bash
python -m pip install -r requirements_test.txt
ruff check custom_components tests scripts
mypy
python scripts/check_protocol_imports.py
node scripts/check_panel.mjs
python -m pytest
```

Every flow and every EEP needs tests (coverage must stay at 95 % or above). Anything that changes
what is stored (entry data or options, device subentry data, the stores under `.storage`) needs
a version step and a migration in `async_migrate_entry` (bump `MINOR_VERSION` of the config flow
and `SUBENTRY_SCHEMA` together), tested from the oldest layout up (`tests/test_migration.py`)
and for devices the catalog no longer knows. `docs/devices.md` is generated by
`python scripts/gen_device_docs.py`.

The sidebar panel (`frontend/`) has no build step: `monitor-panel.js` loads `shared.js`,
`texts.js` and `takeover.js` with its own version query. A new text goes into both languages
of `texts.js`; `scripts/check_panel.mjs` (Node.js 22.7 or newer) checks that every file loads
and that English and German have the same keys.
